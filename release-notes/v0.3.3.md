## What's new (preview)

The GPT-SoVITS speech synthesis component can now run its service and synthesize speech, and the agent can play speech on the system default output device, for example the GPT-SoVITS sentences of a reply.

- `startService(model)` starts the installed package's API (`runtime/python.exe api_v2.py`) on the `port` option and loads the voice model's GPT and SoVITS weights. The service, and with it the model in video memory, stays until `stopService()` or `dispose()`. `status().service` reports the service state, the requested model and whether it is loaded.
- `loadModel(model)` switches the weights; when calls overlap, the last one wins.
- `synthesize({ text, textLang, refAudio, refText, promptLang, signal })` returns WAV bytes. When GPT-SoVITS fails inside inference (for example out of GPU memory) it returns 1 s of 16 kHz silence with success, so a resolved call is not proof of real speech. An abort through `signal` or the 120 s timeout only releases the caller: GPT-SoVITS keeps computing, and later calls wait behind it. The returned audio is normalized to -20 dBFS RMS with peaks at most -1 dBFS (silence unchanged).
- `install` and `useExisting` stop a running service first and start it again with the same model when they end.
- A service that exits on its own is reported as failed with its last error output; it is not restarted.
- `POST /v1/play?rate=<Hz>` queues a clip: the body is PCM s16le mono samples at 8000-48000 Hz, up to 60 s. Clips play one after another without a gap; the answer is `{ id }`. When a clip's rate differs from the one before it, the output device is reopened at the new rate once everything before it has been played.
- `POST /v1/playback/stop` stops the current clip and drops the queued ones.
- A `playback` event `{ state, id }` reports each clip's `start`, `end` or `stopped`. An `error` event with code `playback_failed` is sent when a playing clip is cut because the output device stopped and did not come back within 2 s (that clip ends with `stopped`), or when the device cannot be opened for queued clips (those clips end with `stopped`). A change of the default output device moves playback to the new device without either.
- `/v1/status` reports `playback: { playing, queued }`.
- The client adds `VoiceAgentSupervisor.play(wav)` for PCM 16-bit mono WAV files (other WAVs are rejected with `PlaybackError` `PLAYBACK_UNSUPPORTED_WAV`, and `PLAYBACK_NOT_RUNNING` while the agent is not running) and `stopPlayback()`.
- A `playback` event can arrive before `play()` resolves with its id; ids start at 1 in each agent process, and clips outstanding when the agent exits or restarts may end without an event (an agent shutdown can still send `stopped` for them before the event stream closes). Await each `play()` before the next, and before `stopPlayback()`, to keep the order.
- Playback is independent of the microphone; recognition is unchanged.

## Changed

- The client is 0.3.4.
- The REST / SSE API gains the playback endpoints and the `playback` event; its API version stays 1. An agent without playback answers 404 to `POST /v1/play`.
